## Rulings that must survive (a fresh session will otherwise re-litigate these)

- **`packages/typeset/src/**` relative imports carry an explicit `.ts` suffix**,
  not `.js`. Node's type stripping does not rewrite specifiers, so `.js` breaks
  `node --test`; `tsc` rewrites `.ts` on emit. This **deliberately differs** from
  `apps/api`, which uses `.js`. Erasable syntax only in that package.
- **`apps/api/src/latex-worker.ts` must have zero relative imports into
  `apps/api`.** It may be loaded by plain Node type-stripping rather than tsx,
  where `apps/api`'s `.js`-suffixed specifiers do not resolve — dev would break
  while `dist/` worked. Pass values through `LatexWorkerRequest` instead.
- **Worker-per-compile, not a reused worker.** A reused worker cannot be
  `terminate()`d without destroying the next compile's host, so it must fall back
  to a cooperative stop — exactly what does not work against a synchronous engine.
  Real cancellation is brief 44's point.
- **Video cover geometry**: native aspect at a 640 bound (`fit: "inside"`), not
  the audio path's square crop and not a forced 640×360. Card letterboxes with
  `object-contain`. Books and audio geometry untouched.
- **The cover route writes through to `coverPathFor(coverOwnerId(row))`** — the
  shared thumbnail — because that is the only path `GET` and `hasCover` read.
  Writing to `row.id` for a converted row would be an invisible orphan.
- **No ownership check on the cover route** is a decision, not an omission (D40):
  `books` has no `user_id`, the library is install-wide, and setting a cover is
  strictly less privileged than the already-unscoped delete route.
- **A cancel is never offered where it cannot be taken.** A sibling profile's
  project 404s at the cancel route, so `busyMessage`'s third branch makes no
  offer, and the 409 for an in-process-only slot holder omits `runningProjectId`
  because that id addresses a deleted project.
- **Never delete a failing assertion to go green.** In brief 39's integration
  pass, a failing test meant behaviour *legitimately* changed, and each assertion
  was updated to check the new correct behaviour. `unsupported.test.ts`'s
  exemplars were swapped to still-unsupported commands (`\textsc`, `longtable`)
  rather than relaxed to expect the new codes, because those tests exist to prove
  the unsupported-vs-undefined distinction.
- **A "re-check the flag" fix on a synchronous-resume path needs an `await`.**
  The microtask queue drains fully before any timer or I/O callback, so a check
  with nothing to yield on cannot observe a flag a *request* set. This was proven
  with a three-way rig after the controller specified the fix wrongly.
